# Outcome log and usage

The outcome log, usage figures at exit and live usage. Read it before changing `internal/outcomes`, `internal/usage`, `internal/uselive` or `internal/usageapi`.

- `internal/outcomes` is the outcome log: one goroutine appends a JSON line per record (a ship's guard is a second appender, a separate process writing its own short `guard_denied` line) to `$ADMIRAL_HOME/outcomes/<YYYY-MM>.jsonl` (month of `ts`, UTC), queues 1024 records and drops the rest (`Enqueue` passes `outcomes.ErrDropped` to a dropped record's `onDone`), and logs a failed write once until one succeeds.
- Admiral only writes the log; `admiral outcomes` reads it back.
- A line over `outcomes.MaxLine` and any name that is not a regular file, and nothing else reads it.
- `ships.Service` feeds it: `launched` from `Service.LaunchOrder`, the one launch path for `serveLaunch` and autopilot, which holds the order's key while it runs so a second launch of that order gets 409, and sets `"autopilot"` from the request (and only then does `Run` follow the ship), `needs_you` and `underway` from the status each pass of `Run` sees against the last (`internal/ships/outcomes.go`; a stop whose reason changes is one stop, and a ship no hook has spoken for needs you with reason `idle`), `ended` when a pane is dead without `@admiral-ended` (also at start-up, before an exit-0 ship is killed) `dismissed` from Dismiss, `stopped` from Stop ship (a live ship gets an `ended` with signal `KILL` first, queued by `recordKilled` in `internal/ships/input.go`; an anchored one follows Dismiss's order), `answered` from the inbox (`internal/inbox`, ADR 0016).
- `ended` carries the parsed `$ADMIRAL_REPORT` (at most 1 MiB; `null` and a log line when invalid), and once it is written the writer sets the session option `@admiral-ended` and deletes the report and inbox of a ship that was dismissed or sailed off.
- Admiral kills such a ship whether or not the log works (`Service.killShip`), so one killed while its `ended` fails loses that `ended` and keeps its files; a dead pane still in tmux is retried at the next start, and Dismiss queues a failed `ended` once more before `dismissed`.
- The deletes go through an `os.Root` on `$ADMIRAL_HOME` and are skipped, keeping the files, while a launch is under way (a name is not known before `Launch` returns) or when a newer ship's track holds the name: none leaves the home, though a link swapped in inside the home can still send one elsewhere within it.
- `launcher.ShipFiles` builds the report and inbox paths for both the environment and the cleanup.
- The needs-you tally survives a restart in the session options `@admiral-needs-count`, `@admiral-needs-s` and `@admiral-stop-since`. A session removed with no dead pane gets no `ended`.
- `admiral outcomes` (`internal/cli/outcomes.go`) prints the log: it reads the month files directly, line by line, and filters on `ts` and `ship`, with `--ship` mapped through `launcher.Slug`.
- The live usage store (`usage.Store`, wired once in `cmd/admiral/main.go`) keeps the latest live figures in memory and writes nothing: per ship and session, tokens and money with the time a source saw them (`Figures`, `LastLive`), and per harness login (the identity dir, `config.IdentityDir`) the quota windows with their age (`Quota`; a window past its reset reads as unused, and a restart starts empty).
  - `LastLive` skips a session that has spent nothing, so the chat's `/clear` records the cost of the session it ended.
  - Feeds in `internal/uselive`: `Claude` parses each pane's `@admiral-statusline` (`usage.ParseStatusline`) on a 2 s loop that makes one batched tmux read through `sessionhost.Server.ReadLivePanes` (ships and the chat, not crew boats); `Codex.Frame` takes every frame `shipconv`'s observers read (`shipconv.Service.LiveFrame`, ships only: `thread/tokenUsage/updated` per thread, summed per ship, and `account/rateLimits/updated` for the login); `Copilot` re-sums a ship's events file (named by its `@admiral-transcript`, opened through `transcriptfs`) when its size or time changes, and gives no quota.
  - Unverified: the Codex rate-limits frame and the Claude status-line sample are built from documented shapes, not captures (`internal/usage/testdata/README-live.md`).
  - `internal/usageapi` serves the totals and quota (`GET /api/usage`, `GET /api/ships/<session>/usage`; see `docs/api.md`): it scans `outcomes/*.jsonl` per request through `outcomes.MonthFiles` and adds the live store's figures.
- Usage at exit (`internal/ships/usage.go`, `internal/sessionhost/rollouts.go`): `queueUsage` reads the pane strings inline (the pane is gone once the ship is killed) and the files on a goroutine. The Codex hook appends each rollout path to the pane option `@admiral-rollouts` (32 paths); `Launcher.CloseCrew(ctx, boat)` appends a closed boat's `name:harness:path` entries to the ship session's `@admiral-closed-crew` (64 entries), which the ship's exit adds like a live boat. A failed `usage` write clears the guard so `retryEnded` queues it again.
