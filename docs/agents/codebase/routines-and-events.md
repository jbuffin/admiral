# Routines and the Lookout

Routines, the scheduler, event routines, standing orders and the Lookout. Read it before changing `internal/routines` or `internal/lookout`.

- `internal/routines`: routines (when, do, before acting, notify), their trigger log and Hold fire, under `$ADMIRAL_HOME/routines/` (`<fleet>/routines.json`, `<fleet>/triggers.jsonl`, `<fleet>/hold.json`, and `hold.json` for all fleets), written only there; routes in `service.go` (`docs/api.md`).
  - A save is validated in `Store.validate` without `autopilotgate.Check`, which posts an Inbox notice.
  - `ParseCron` and `Schedule.Next` (`cron.go`) are the cron parser and the next-run-after-t the scheduler uses. `internal/cli/hold.go` is `admiral hold`.
  - `scheduler.go` is the scheduler (`Scheduler.Run`, started in `cmd/admiral/main.go` through the adapters in `routines_wire.go`): it fires each enabled routine from its trigger log and `Changed()` (routine saves, ship changes, resource changes), holds cap and resource waits itself, launches under the `routine:<id>` key and counts the circuit breaker from the trigger log.
  - `events.go` decides routines that run on source events: `TierOf`, `Decide` (skip filters, repo allowlist, effective action, then the budgets that drop it to A1: spend, quiet hours, rates and dedupe; `EventTop` is A5), `Scheduler.HandleEvent` (matches enabled `on` routines, records one trigger each, files cards and proposals through `Acts`, and launches a Launched decision through `launchEvent` in `eventship.go`) and `Store.Records`, the fleet-wide log reader; the cron paths skip `on` routines.
  - `standingorders.go` keeps a fleet's Checks and Guidance in `<fleet>/standing-orders.json` (`Store.StandingOrders`, `SetStandingOrders`; a count, length or duplicate failure is `ErrInvalid` naming `checks[i]` or `guidance`); `standingorders_service.go` serves them with the fleet's effective Limits and Copy (the orders file is written first and put back when `config.Manager.CopyLimits` is refused); `draft.go` is the standing-orders and routine drafters (one Strong judge call each, prompts in `standingorders_writer.md` and `routinewriter.md`; a Check or Guidance the prose doesn't hold, after whitespace collapse, is dropped and named in `problems`; nothing is saved).
  - `Launcher.Guidance` appends the Guidance to a worker-launched ship's prompt (`launcher/guidance.go`); `launchEvent` sets `WorkerLaunched` and the event text on an event ship; `wireStandingOrders` in `routines_wire.go` assigns the reader after the store exists.
  - AdmiralBot reads standing orders through `get_standing_orders` and never changes them.
  - `kept.go` keeps each routine draft the routine drafter answers, in memory per fleet for an hour (`GET /api/fleets/<key>/routine-drafts/<id>`); AdmiralBot's `draft_routine` tool posts to the drafter and answers a summary and the link where the engineer saves it.
- The Lookout (`internal/lookout`): `Enrich` runs one tool-less judge call per event whose routines pass their filters and returns validated fixed fields; `Acts` turns a Reported decision into a chat event card (`internal/chat/eventcard.go`) and a Proposed one into an event proposal in the Inbox (`internal/inbox/event_proposal.go`, the text in `$ADMIRAL_HOME/inbox-events/<id>.json`, read by a route the actor guard denies).
  - `Acts` also posts a launch card (`internal/chat/launchcard.go`, chat kind `launch_card`) for each event launch that started a ship, which `HandleEvent` hands it with the saved record; a proposal accepted from Peek posts none.
  - Undo (`internal/routines/undo.go`) stops the ship through `Service.Stop` (wired in `cmd/admiral` over `ships.Service.Stop`) when `EventLaunchedShips` lists a ship whose `Trigger` is the record's own id, so a ship that deleted its clone is still stopped and a newer ship that reused the name is not; it removes `checkouts/<session>` through a root on `$ADMIRAL_HOME` unless such a newer ship holds the name, and marks the record.
  - Promote (`internal/routines/promote.go`, route `…/runs/<trigger>/promote`) offers a restricted Draft fix launch's work to a normal ship: `internal/promote.Read` checks the clone's alternates are still the one `Checkouts.Make` wrote, takes the base as the merge-base of the clone's branch and Dir's HEAD, refuses commits or a diff that touch `.admiral/` or harness config (`internal/promote`'s `harnessPaths`) or add a symlink, and reads an uncommitted diff through a scratch index when there are no commits; the route stops the ship, launches through `Service.Launch` (wired over `ships.Service.Launch`) with `launcher.Request.StartFrom`, which makes the new `checkouts/<session>` clone, fetches the branch from the restricted clone (or applies the diff) and writes no event file, and marks the record with a `promote_of` line in `triggers.jsonl`.
  - The launcher carries the route's tip in `StartFrom.Tip`, fails when its own read differs, and runs the same refusals and the merge-base again in the new clone against the fetched tip (`promote.Verify`).
  - All of it runs git through `internal/neutralgit`, which turns `refs/replace` and grafts off.
  - A Draft fix ship's profile denies writes to `<checkout>/.claude` and `<checkout>/.mcp.json`, so it cannot plant settings its own relaunch would load. `Scheduler.LaunchProposed` launches a proposal.
  - An event launch is by level: A3 is a restricted ship (the decision's `restricted` profile) in a clone, A4 a normal ship in its own `git clone --shared` under `$ADMIRAL_HOME/checkouts/<session>`, A5 only for a Commodore spec (a Commodore spec below A5 is an A1 proposal, reason `commodore_below_a5`; any other spec at A5 runs at A4).
  - Every event ship reads the Lookout's title and body from `<clone>/.admiral/untrusted/event.md` (`Enrichment.Text`, with the title and a metadata line when the Lookout is off), which reaches no trigger record, card or proposal; a relaunch whose `req.Session` names an existing clone keeps it.
  - The A4/A5 clone keeps the event file out of the engineer's checkout but is not confinement: its `origin` is that checkout, so a normal ship could push into it.
  - The launch never waits and never retries: a `launcher.Error.Cause` of `global_cap`, `quota_hold`, `resources`, `host_unknown` or `routine_busy` becomes an A1 proposal with that reason, `issue_held` (another ship or a launch in flight already claims the event's issue; `launcher.Error.HeldBy` is the holder's session, empty for a launch in flight) becomes a `skipped` record with reason `ref_has_ship` and `held_by`, and any other refusal a `failed` record.
  - An accepted proposal that meets `issue_held`, or a PR or issue a listed ship now holds, writes the same `skipped` record, launches nothing and answers 409 with an error that wraps `ErrBusy` and says what holds the item (the launcher's message, or `this PR or issue already has a ship (<session>)`).
  - Before an event the breaker marks the routine's ships that ended failed (`tripEvent`) and counts three in a row as for a scheduled routine; `EventLive` counts a fleet's live event ships and dedupe keys from the trigger records:
  - only underway and needs-you ships hold a worker slot, while an ended one keeps its routine and dedupe key until dismissed; `EventLaunchedShips` is the dedupe view for event keys (`EventLive` maps each held `dedupe_key` to its ship's session; a key held by a live event ship skips the event in `Decide` after the skip and allowlist checks, whatever the routine's Before acting; `HandleEvent`'s held-PR skip keeps that order) and includes a ship an accepted event proposal launched (`Via: proposal`, flagged `Proposal`), so its event stays deduped while it is live;
  - `EventShips` leaves those out, and `countWorking` skips them, so the cap, the wall clock and Stop all never touch it.
  - A plugin event's Lookout `dedupe_key` starting `gh:` is dropped, so that namespace holds only keys Admiral reads from a verified ref.
  - The wall clock (`wallclock.go`) runs in `Scheduler.tick` and sets `Run`'s sleep to the earliest deadline of a live worker ship (launch plus the fleet's `wall_clock_minutes`; `ADMIRAL_WALL_CLOCK_MINUTE` shortens the minute in e2e), so an event-only fleet is still checked on time.
  - It calls `Scheduler.EndHarness`, wired to `sessionhost.Host.EndHarness`, which sets the `stopped-by` session option, sends TERM, then KILL (after a grace, or as soon as the leader is gone), to the pane's process group and to every descendant it saw in the process table before the TERM, and leaves the dead pane (`remain-on-exit`); a child that called `setsid` and was reparented before that read is out of reach, as it is for `kill-session`, then marks the launch record failed with the reason once per record.
  - Stop all worker-launched (`workerships.go`) stops the same ships through `Service.Stop`.
  - A Promote's `promoted_at` counts as a launch in `spendAndCounts`. `cmd/admiral/routines_wire.go` wires them.
