# Permission log and allow rules

The permission log and the allow rules built from it. Read it before changing `internal/permlog` or `internal/allowrules`.

- The permission log (`internal/permlog`): every permission prompt a ship and its crew boats hit, and how it was answered, one append-only file per ship, `$ADMIRAL_HOME/permissions/<ship>.jsonl` (0600; lines capped at 16 KiB, the file at 8 MiB).
  - Its lines are events: `launch` (written by `Launch` before the session starts: harness, fleet key, and repo, the GitHub origin's `owner/repo` (as `repokey.Key` reads it, the key launch looks allow rules up by) or else the checkout's real path), `ask` (the call, normalized to `permlog.Call`: tool, kind, command, paths, URLs, cwd, and the harness's own narrowest forms, Claude Code's `permission_suggestions`, Copilot's command identifiers and Codex's `proposedExecpolicyAmendment`), `answer` (allow or deny, and who: `person`, `reviewer`, `timeout`, `unattended` or `unknown`) and `card` (an in-place card's answer, written by `serveAnswer`).
  - `permlog.Read` folds them into one `Record` per prompt; a person's answer that a card gave between the prompt and its answer is `via: card`, any other `via: terminal`, and a card's deny answers a prompt no hook closed. Each harness's prompts come from its own first-party data.
  - Claude Code (ships and crew boats): `admiral hook` (`internal/cli/hookperm.go`) logs `PermissionRequest` as an ask by a person, keeps it open in `permissions/.open/<pane>`, and closes it as allowed on the `PostToolUse` or `PostToolUseFailure` with the same tool and input, or denied on `Stop` (no subagent running), `UserPromptSubmit`, `Interrupt` or `SessionStart`.
  - A Codex ship: its app-server observer (`permlog.CodexTracker`, fed by `shipconv.Service.Permissions`): a `requestApproval` reaches the TUI only when the reviewer left it to a person, so the item's status answers it (`declined` is a deny, a turn that ends on it too), and `item/autoApprovalReview/completed` is the reviewer's own verdict or its timeout.
  - A Codex crew boat has no observer and Codex runs `PermissionRequest` before its reviewer, so its hook-logged answers are `unknown`.
  - Copilot (ships and crew boats): the hook reads `permission.requested` and `permission.completed` from the session's `events.jsonl` on `notification`, `postToolUse` and `agentStop`, from the offset kept in `permissions/.read/<session id>`, and `decisionSource` says who (`human_response`, `assisted_approval`, `unattended_fallback`).
  - The hook finds the home from `ADMIRAL_CREW_DIR` and the ship from its pane's session.
  - The log outlives the ship, so a round's prompts can be read after it ends; a name reused by a later ship appends a new `launch`, and each record carries the launch it came in (`launched`). The ship's state keeps only its reason token.
- Allow rules (ADR 0046).
  - `internal/allowrules` keeps each fleet's allow rules and skipped allow rule proposals in `$ADMIRAL_HOME/allow-rules.json` (`{"fleets":{<key>:{"rules":[...],"skipped":[...]}}}`), re-read on every call and written under `allow-rules.json.lock`, because `admiral crew` inside a ship reads it too; a corrupt file refuses every write.
  - A rule is `{harness, repo, rule, pattern, added}`: a Claude or Copilot rule carries its harness's rule text (`Bash(gh pr view:*)`) and a repo, which is `launcher.RepoKey` (the github.com origin's `owner/repo`, else the checkout's path); a Codex rule carries a `prefix_rule` pattern and no repo, since it covers every repo of the fleet.
  - Use `Launcher.AllowRules()` to change the store: after a change to a fleet's rules it rewrites `rules/admiral.rules` in every fleet's Codex `CODEX_HOME` (`SyncCodexRules`; fleets that share one share the file, and a file with no rules left is removed).
  - The engineer's own `*.rules` files are never touched, and no other harness file is written.
  - At launch, `ruledFlags` adds the rules to a ship or crew boat that is not restricted, keyed by the ship's checkout (a boat uses the ship's `dir` option): a Claude launch with rules for its repo gets `--settings $ADMIRAL_HOME/harness/claude-settings-<hash>.json`, the shared hook settings plus `permissions.allow`, named for its content so a live ship's file never changes, and with none it keeps the shared `claude-settings.json`; a Copilot launch gets one `--allow-tool=<rule>` after `--plugin-dir` for each rule for its repo (`shell(gh pr)`, `url(<host>)`, `write(<path>)`), which Copilot checks before its assisted judge; a Codex launch rewrites its own `CODEX_HOME`'s file when the fleet has rules there.
  - A rule that can't be written is logged and the launch goes on.
  - The autopilot args allowlist has no `--allow-tool`, so only Admiral adds one.
  - `allowrules.Candidates` turns logged prompts (`permlog.Record` plus the launch's restricted flag and trigger tier) into the rules worth proposing, merging repeats into a count, and returns a reason for each prompt it drops (one not allowed by a person, from a restricted ship or a T2–T4 launch, already allowed or skipped, or refused by the never list in `never.go`), except a log line read again and a non-allow suggestion that sits beside an allow rule.
  - The rule is the harness's own narrowest form: Claude Code's `permission_suggestions` (`addRules` only), Copilot's `shell(<identifier>)` or an absolute `write(<path>)`, and for Codex the command's argv up to its first word that is neither a lowercase plain word nor a long option without a value (`git log --oneline` gives `[git log --oneline]`; `-o` or `--output=x` ends it).
  - The never list is command prefixes grouped as the glossary names them; names match with case folded, a prefix rule is refused when it overlaps any entry in either direction (since `shell(gh pr)` also allows `gh pr merge`), an exact command only when it falls under one, a long flag matches by any prefix of three letters or more, and an option before a subcommand (`git -C . push`) is refused for any program that has a subcommand entry.
  - File rules stay in the worktree or in the ship's own report (`reports/<ship>.json`) and own `inbox/<ship>/` (compared with the logged ship, case folded); another ship's, `inbox/_admiral/` and any glob in the ship or session segment are refused. MCP and URL rules are always refused.
  - `internal/allowrulesapi` serves a fleet's list and the two remove routes (`docs/api.md`) over `Launcher.AllowRules()`, for the fleet's Allow rules page in Preferences.
