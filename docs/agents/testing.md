# Testing

How Admiral's tests are set up. The rules for what to test are in [`AGENTS.md`](../../AGENTS.md).

Admiral keeps its data in `$ADMIRAL_HOME` (default `~/.admiral/`). Every test starts the binary with a fresh temporary one on a free port, so tests never touch yours.

Tests sit at two seams. `e2e/` (Go) starts `bin/admiral` and drives it over HTTP and WebSocket. `web/e2e/` (Playwright, WebKit) loads the page at iPad landscape, iPad portrait, desktop and phone (402x874) sizes. The phone project runs only the inbox specs, `phone.spec.ts` and `launch-phone.spec.ts` (its `phone.spec.ts` suffix matches the project's unanchored pattern); the other projects skip `phone.spec.ts`. Vitest covers pure UI state logic only.

Tests that launch ships use the fake harnesses in `e2e/fakeharness/` (`claude`, `codex` and `copilot` are symlinks to `fake.sh`). A test puts one as the `executable` of a fleet and passes two variables in the fleet's `env`: `FAKE_RECORD_DIR` (where to record) and `FAKE_CUE` (an optional cue file). Started in a ship's pane, the fake writes `<FAKE_RECORD_DIR>/<tmux session>/` (a crew boat, whose window has `@admiral-crew-name`, writes `<FAKE_RECORD_DIR>/<tmux session>/crew/<crew name>/` instead) with `harness`, `argv` (each argument followed by a NUL byte), `env` (one `NAME=value` per line), `cwd`, `name` (the `@admiral-name` option as read at start), `options` (all session options at start), `window-options` (the options of its pane's window at start), `dirs` (`inbox=yes reports=yes` when `$ADMIRAL_INBOX` and the directory of `$ADMIRAL_REPORT` existed before the harness ran anything, `no` for each that did not, `reports=unset` when `$ADMIRAL_REPORT` is empty) and last an empty `recorded` file to wait for. Then it runs the cue file, one cue per line: `hook <needs_you|working>` runs `tmux set -p -t "$TMUX_PANE" @admiral-state <state>` (a bare `set -p` would land on the session's active pane, not a crew boat's), `event <Event> <json>` runs every handler of every group the Claude hook bundle holds for `<Event>` whose matcher matches, each with the JSON on its stdin (it needs `jq`; a matcher is a regex tested against the payload's `tool_name`, or `notification_type` for `Notification`, and a group with none always matches; the match is unanchored, so `Bash` also matches `BashOutput`, looser than Claude; each handler appends `<Event>`, its exit code and its command, tab separated, to `handlers` and writes its stderr to `handler-<n>.stderr`, n counting from 1; it appends the event name to `events-done`, one line per cue, and a fault of the fake itself goes to `event-error`; a handler's non-zero exit is not a fault), `bell` rings the bell, `sleep <n>` waits n seconds, `exit <n>` exits with status n, `lines <n>` prints n numbered lines (`line 0001`…) in cycling SGR colours, `altscreen` switches to the alternate screen with application cursor keys and bracketed paste on and prints `ALT SCREEN`, and `wait <name>` blocks until the file `<tmux session>/<name>` exists in the recording directory. When the cues end it puts the terminal in raw mode (`stty raw -echo`), creates `cues-done` and stays running unless a cue exited; from then on it records every byte it reads from the terminal, exactly as received, in `stdin` (a test sends input only after `cues-done`). The same protocol is in the header of `fake.sh`. Tests that run tmux set `TMUX_TMPDIR` to a temporary directory and talk to tmux only with `tmux -S <home>/tmux.sock`.

Tests that need `gh` put the fake in `e2e/testdata/fakegh/gh` first on Admiral's `PATH` and steer it through `$FAKEGH_DIR`. Its header lists every call it answers: `--version`, `auth token`, `api graphql` (the GitHub plugin's search) and REST `api` calls. A REST call takes `-X`/`--method`, `-f`/`--raw-field`, `--hostname`, `--input FILE|-` and one endpoint; the method is GET unless a flag or a field says otherwise. The fake refuses `-F`/`--field`, `--jq` and `--template` (exit 2), so a test fails if Admiral lets an item's text be read as a file, or leans on gh's own filtering. Each call writes `$FAKEGH_DIR/calls/call.*/` with `argv`, `env`, and for REST `method`, `endpoint`, `host` and `stdin`. A test scripts an answer with `fakeGH.rest(key, method, endpoint, status, body, stderr)`: a status of 300 or more exits 1 with the stderr, as gh does, and a call with no canned answer exits 1. `callsTo` and `restCalls` read the calls back, and `restCall.field` finds a body field in a `-f` argument or in JSON on stdin. A test that must not reach GitHub asserts that `restCalls()` is empty.

The server tests that connect through the Mac's own LAN address skip, with a message, when that address doesn't answer. On CI (`macos.yml` and the release) they fail instead.
